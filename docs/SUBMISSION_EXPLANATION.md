# Technical explanation

Talk to Your Building answers from deterministic building tools. The language model interprets the request and explains the tool result. It does not invent distances, room counts or routes.

## Stack

- Python 3.12, `uv`, Shapely and NetworkX for geometry and routing.
- Claude through the Anthropic SDK for conversation and plan-image observation.
- FastAPI serves `/api/v1` for the web session. The React map is a separate frontend.
- Local JSON and SQLite store edited buildings and room reports. Benchmark questions use a fresh map and a temporary directory.

## Route models

The default profile is kit 1.1.0: door-to-door walks about 15 cm off the walls, stair and lift costs from floor elevation, and no outside shortcut. Public labelled answers use this profile.

`synera-industrial` keeps those walk lengths and adds forklift eligibility: openings must be at least 3 m, and production, assembly and additive bays can be a start or a delivery stop but not a shortcut. Pedestrian doors fail the 3 m rule. This profile is not used for the kit benchmark answers.

If a room has no validated interior walk, the inherited kit fallback estimates 1.5 times the straight-line distance. That estimate is not a drawable path.

## What a judge can run

```bash
uv run --env-file .env python -m benchmark.evaluate data/test --agent final_agent.benchmark:answer --submission-csv team_answers.csv
uv run python -m benchmark.sunday path/to/sunday_input
```

The public CSV is written only when every answer is nonempty and, for `data/test`, the 145 template IDs are covered. The Sunday command exits without an answers file until the organizers announce the schema.
